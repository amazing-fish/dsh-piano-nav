# 鼠标横向体验：10 个候选改进与首轮建议

状态：已获用户批准，按 1/2/3/5/10 实现，等待实验分支审阅。基线：`a8894d17371f7e0843d53cbb5539b4c07bc0de54`（已合入 1.3.1 源码，npm latest 仍为 1.3.0）。
实验分支：`experiment/horizontal-pointer-experience`。本轮已实现与验证交互，未合入主分支，未发布 npm。

## 现状与核心判断

上下移动已有连续 Y 坐标、rAF 合帧及纯指针轻路径。横向移动尚未形成连续响应：
X 只参与命中开关，波形强度完全由 Y 与语义选中决定。因此先解决进入、退出与边界的一致性，
再评估是否新增“X 控制力度”，能减少对现有上下手感的干扰。

源码依据（均固定到基线）：

- [strip.ts](https://github.com/amazing-fish/dsh-piano-nav/blob/a8894d17371f7e0843d53cbb5539b4c07bc0de54/src/client/strip.ts)：`barWidth` 使用基宽 10/24、峰值 48、Y 高斯波形；`keyHitAt` 使用当前绘制宽度加 3 CSS px；`applyPointer` 只存储连续 Y 偏移。
- [styles.ts](https://github.com/amazing-fish/dsh-piano-nav/blob/a8894d17371f7e0843d53cbb5539b4c07bc0de54/src/client/styles.ts)：轨道宽 58；指针跟随时移除宽度过渡，退出后恢复 82ms；预览显示/隐藏采用 90/110ms 过渡。
- [pointer-browser.mjs](https://github.com/amazing-fish/dsh-piano-nav/blob/a8894d17371f7e0843d53cbb5539b4c07bc0de54/scripts/pointer-browser.mjs)：已有连续 Y、快速反向、空白不导航、合帧和生命周期回归；尚无完整的 X 进出扫描和快速横向折返轨迹。

一个可核验的静态例子：普通非当前键、Y 恰在键中心、等待上一段动画结束时，
从右侧进入的命中范围约为 X≤13（10+3）；一旦选中，目标宽度变为 48，命中延伸至 X≤51。
退出且缩回后，重新进入又需靠近 X≤13。这是随状态变化的边界，不能只靠增加动画时长解决。
这里的 X 相对轨道左缘，单位是 CSS px；不是 Windows 真机测量值，移动中的瞬时边界还受绘制宽度影响。

## 10 个候选改进

| # | 候选 | 预期体验及设计方向 | 代价或边界 | 建议 |
| --- | --- | --- | --- | --- |
| 1 | 进入时平滑起势 | 从当前实际宽度起步，短暂升至目标波形，避免一命中就从 10 跳到 48；Y 的波峰位置继续实时跟手。 | 不能给所有指针帧重套 CSS 缓动，否则上下移动又会拖尾。 | 首轮 |
| 2 | 退出时连续收势 | 从离开瞬间的绘制状态收回；高亮、波形、提示卡各自有明确退出规则，避免有的立刻消失、有的仍在收缩。 | 只有视觉可以短暂退场，空白处点击不能继续导航。 | 首轮 |
| 3 | 明确进入/退出边界 | 分清候选目标、视觉幅度、点击命中；减少“第一次要靠很近，第二次很远仍命中”的不可预期感。 | 点击保留实际绘制范围 + 小容差；不恢复整块 58px 隐形导航热区。入口/退场规则需要一并设计。 | 首轮核心 |
| 4 | X 连续调节波形力度 | 候选为靠近轨道主干时更强、向正文退出时渐弱；Y 管波峰位置，X 管整体幅度。 | 若要求从右侧空白处预热，与既有“空白不悬停”契约有取舍；先限定在有效区域内实验，不默认扩大热区。 | 第二轮对照 |
| 5 | 快速折返立即接续 | 退出到一半又进入时，从当前绘制状态转向新目标；取消旧退场，避免先缩完再展开或迟到回弹。 | 只保留一个有效输入/退场过程，鼠标停下后无常驻动画循环。 | 首轮 |
| 6 | 斜向移动稳住目标键 | 横向移动伴随少量 Y 抖动时，避免相邻键/预览反复切换；只在相邻中心分界附近研究小幅稳定区。 | 不锁死明显的纵向切键，不改变完整窗口和键盘导航。 | 第二轮按复现决定 |
| 7 | 提示卡按阅读意图显示 | 过滤一次快速掠过造成的闪卡；同一键横移不重复显隐或改写内容，键盘仍能直接获得预览。 | 首次短延迟可能显得慢；延迟值须对照体验后再定，不当作既定改进。 | 第二轮可选 |
| 8 | 预览卡可横向抵达 | 鼠标从键移向预览后，仍能继续读；可研究只保留预览，导航命中立即结束。 | 当前 tooltip 为 pointer-events:none，离轨即关闭；这是新增交互契约，需要明确是否要可选中/复制正文。 | 暂缓，单独决策 |
| 9 | 缩小透明交互拦截 | 检查 58px 容器中未绘制区域是否影响底层点击、文本选择或横向经过；需要时使非导航区域穿透。 | 源码可确认透明容器接收事件，但尚未证实用户现场发生遮挡；不能破坏轨道滚轮浏览。 | 按现场证据决定 |
| 10 | 横移保留轻量更新与输入隔离 | X-only 不重建历史、语义或投影；稳定目标不重写预览，重复采样合并；键盘/失焦/会话切换能覆盖旧指针输入。 | 复用现有脏标记与生命周期，不新增第二套调度器；减少动画模式单独验证。 | 首轮约束 |

## 已批准的首轮选择

**首轮选择 1、2、3、5、10。** 只解决横向进出不连贯和边界不稳定，保留当前 Y 连续波形、
语义配色、点击展开过程、历史入口和正文导航职责。进入/退出时允许一个有限的幅度过渡，
指针持续纵向移动仍使用已有连续坐标，不让宽度过渡追逐每帧目标。

首轮不预设更长、更夸张的琴键，不将“鼠标进入整片空白区域”作为预览或点击依据。
单纯把 width 换成 transform:scaleX 也不能解决二值命中与进出状态问题，先保留 width 实现。

4 是第二轮真正改变手感的实验项；6、7、9 依第一轮轨迹与现场反馈决定；
8 涉及“预览是否可进入并复制”的产品选择，单独讨论。

## 实施与验证

1. 固定同一批语义键、视口和数据，比较主分支与实验分支：左入/右入、同 Y 慢扫、快速掠过、
   边缘来回 1–3px、退出半途折返、斜向跨键、移至空白后立即点击。
2. 记录每帧 X/Y、目标键、实际绘制宽度、预览状态、导航次数、几何读取及重建计数；
   判定空白无误导航、反向无旧状态回弹、同键预览稳定、X-only 无语义/历史重建。
3. 回归上下扫动、滚轮窗口、折叠/展开、加载中、键盘覆盖指针、失焦/切会话/卸载和减少动画。
4. Windows Edge/Chrome 在用户实际缩放下验收，再按 100%/125%/150% 检查阈值一致性；
   浏览器夹具采用实际组件与合成 Session 数据，不能代替完整宿主/Windows 现场验收。
   不以“自动化测试通过”直接宣称丝滑；记录实际帧间隔和手感反馈。

## 实验实现的具体取舍

悬停入口与出口都使用基础键体（普通 10px / 阅读当前键 24px）加 3px 容差，且不超过当前绘制范围。
波形延伸部分不保留悬停；点击仍按实际绘制长度判定，包含尚未缩回的可见部分。
这是为稳定横向边界作出的实验取舍，需结合实际鼠标体验确认。

进入/退出采用 96ms 有限幅度包络，复用唯一 rAF 调度，Y 连续坐标没有额外时间平滑。
减少动画即时完成；折返从当前幅度接续，停下后不保留动画循环。
关键行为已由新增 horizontal-browser 的受控时钟轨迹、原有真实时间 pointer-browser、rail-browser
及契约/集成验证覆盖。设备比例回归为 Chromium DPR 1/1.25/1.5，不能当作 Windows 整体宿主验收。

效果对照使用实际基线/实验代码、同一合成 Session 和同一输入，轨道局部放大 3 倍，
按 16ms 逻辑步进截取，再以 80ms 每图慢放；这不是帧率或输入延迟测量。
